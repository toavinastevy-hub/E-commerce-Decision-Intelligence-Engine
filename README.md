# E-commerce Decision Intelligence Engine (EDIE)

An interactive analytics application that turns e-commerce sales and inventory data into **ranked business
recommendations**. It answers practical questions: which products earn the most profit, which sell a lot but earn
little, whether discounts pay off, what happens if the price changes, which products may run out of stock, and
what a manager should do first.

Built as an MBA Business Analytics portfolio project by **[Your full name]**, Sharda School of Business Studies.

> **Important: the demo data is SIMULATED.** The 18 months of sales and the inventory file were generated by
> `src/generate_demo_data.py` (fixed random seed, so the data is identical every run). The results show how the
> tool works; they are **not** findings about a real company. The app labels simulated data on every screen.

## What the application does

The left menu uses everyday names. The technical name of each screen is in brackets.

| Screen | What it gives you |
|---|---|
| **🏁 Start here** (Data) | One click loads the demo and opens the results. Or upload your own CSV. A quality report lists every problem; rows with errors are excluded (never repaired, never hidden). |
| **📊 The big picture** (Executive summary) | One page: headline numbers, seven key findings in plain sentences, top five actions, trend charts, stock alerts, and a downloadable report. |
| **📈 Explore your sales** (Dashboard) | Interactive numbers, monthly trends, category and product comparison, with date and category filters. |
| **🏷️ Your products** (Products) | Each product is placed in a group (Star, Core volume, Busy but thin, Niche, Low performer) with alert tags. Every label shows its rule and its numbers. |
| **💸 Do discounts pay off?** (Discounts) | For each product: do discounted months earn more or less profit than full-price months? Includes a break-even calculator. |
| **🧪 Try a price change** (Simulator) | What-if: change price, discount, cost and sales and compare with today's numbers. The change in sales is always the user's own guess. |
| **📦 Stock check** (Inventory) | Days of stock, safety buffer, reorder level, suggested order, and alerts for products that may run out or have too much stock. |
| **✅ What to do next** (Recommendations) | A ranked to-do list. Each action has the problem, proof, proposed action, expected benefit, risks and a priority with its reason. |

Technical words are replaced by everyday ones on screen ("sales after discounts", "profit before overheads", "profit margin").
Hover over the small question marks next to the numbers for a short explanation, and open **📖 Words explained** in the left menu.
The exact formulas are in `docs/kpi_formulas.md` and in the "for the curious" boxes inside the app.

## Quick start (Windows)

You need Python installed (the project was tested on Python 3.12). Open a terminal **in the project folder**.

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Your browser opens at `http://localhost:8501`. Click **🚀 Try the demo in one click**. It loads the simulated sales and
stock data and opens **The big picture**.

On Mac or Linux, activate the environment with `source .venv/bin/activate`.

### Other commands

| Purpose | Command |
|---|---|
| Run all automated tests (146) | `python -m pytest -q` |
| Recreate the demo data | `python src/generate_demo_data.py` |
| Rebuild the Excel template | `python src/make_template.py` |
| Data quality report for a file | `python src/data_quality.py data/sales_dirty.csv` |
| Check the KPIs again with SQL | `python src/sql_check.py` |

## Using your own data

**Easiest: the Excel template.** On **Start here**, click **Download the Excel template** (or open
`templates/EDIE_data_template.xlsx`). Fill in the **Sales** sheet, and optionally the **Inventory** sheet, then upload the
file on the same page. You can send the template to colleagues to fill in.

The template helps you while you type:

- **Fill-in rules.** Excel refuses a wrong value (text instead of a date, a discount above 100%, a quantity of 0) and shows a short
  help box when you select a cell.
- **Colours.** A red cell means a required cell is empty in a row that has data. An amber cell means the cost is above the price.
- **A `row_check` column** says "OK" or what to fix. Filter it to anything that is not OK.
- **Filter arrows** on every header, and the header row stays visible while you scroll.
- **A "Read me first" sheet** with a column guide, and an **Example** sheet. Neither is read by the app.

Excel does not apply fill-in rules to values you **paste**. After pasting, look at the `row_check` column. The app checks every row
again on upload, and the row numbers in its messages match the row numbers in Excel.

**CSV also works.** Use these columns (full rules in `docs/data_dictionary.md`):

`order_id, order_date, product_id, product_name, category, quantity, list_price, discount_rate, unit_cost`

For stock analysis add `product_id, current_stock, lead_time_days` (the Inventory sheet, or a separate CSV).
In a CSV, dates must be `YYYY-MM-DD`, `discount_rate` is a fraction (0.10 means 10%) and numbers must have no currency symbols.
Rows with errors are excluded and listed; nothing is repaired automatically.

## How it works

```
CSV files --> Data quality check --> KPI engine --> Segments / Discounts / Simulator / Inventory
                    |                                                   |
              rejected rows                                      Recommendation engine
              (reported)                                                |
                                                          Streamlit screens + downloadable report
```

| Module | File | Purpose |
|---|---|---|
| A | `src/data_quality.py`, `src/excel_io.py` | Validate data; read the Excel template; report errors and warnings with their impact |
| B | `src/kpis.py`, `src/discounts.py` | KPIs and discount effectiveness |
| C | `src/segmentation.py` | Product segments and flags |
| D | `src/simulator.py` | Price, discount, cost and volume what-if |
| E | `src/inventory.py` | Stock position, reorder points, alerts |
| F | `src/recommendations.py` | Ranked recommendations with cross-checks |
| G | `src/summary.py`, `app.py` | Key findings, report, and the Streamlit screens |

```
edie/
  app.py                 the Streamlit application
  .streamlit/config.toml colours and theme of the interface
  requirements.txt
  data/                  sales.csv, inventory.csv, sales_dirty.csv (all simulated)
  templates/             EDIE_data_template.xlsx (fill-in template with built-in checks)
  sql/                   01_totals_check.sql
  src/                   the analytical modules listed above, plus generate_demo_data.py and sql_check.py
  tests/                 146 automated tests
  docs/                  data dictionary, KPI formulas, business case, validation report,
                         portfolio description, interview preparation, demo script
```

## Limitations (read before trusting any number)

- **Simulated data.** Results describe the simulation, not a real business.
- **Gross profit, not net profit.** There are no fixed costs, shipping, marketing or tax in the data.
- **Discount results show a link, not proof of cause.** They compare past months.
- **Sales volume in the simulator is an assumption.** The data cannot measure how customers react to a new price.
- **Inventory assumes steady demand and a fixed lead time.** It ignores seasons, minimum order quantities and storage limits.
- **No customer-level analysis.** The dataset has no customer field, so customer segmentation and lifetime value are not included.
- **No forecasting or machine learning.** All methods are rule-based so each result can be explained and checked.
- **Segments are relative.** Revenue is compared with the median product and margin with the portfolio, not with an outside benchmark.
